### Technical Workflow Deep-Dive

#### Request Lifecycle: AI Marketing Audit

**Preview flow** (`POST /api/audit/preview` at `app/api/audit/preview/route.ts`):
1. **Entry:** Next.js App Router matches `POST /api/audit/preview` and invokes the route handler
2. **Rate limiting:** In-memory `Map<IP, {count, resetAt}>` — rejects with 429 if >10 requests in 10 minutes
3. **Validation:** Verifies URL body param is present and parseable (`new URL(url)`); returns 400 on failure
4. **Scraping:** Calls `scrapeWebsite(url)` from `lib/scraper.ts:25` — fetches HTML via Axios (Chrome UA, 15s timeout), parses with Cheerio, extracts title, meta description, h1/h2 tags, paragraphs (>20 chars), images with alt text, internal/external/social links (11 tracked social domains). All links are deduplicated via `Set`.
5. **AI generation:** Calls `generatePreview(scrapedData)` from `lib/audit.ts:142` — constructs a structured prompt instructing the model to act as a "senior growth strategist," sends to OpenRouter API (`POST https://openrouter.ai/api/v1/chat/completions` with model `openai/gpt-oss-120b:free`, temperature 0.7, max_tokens 4096), and parses the response through `parseJsonSafely()` (`lib/audit.ts:95`).
6. **Response:** Returns `{ success, preview }` with scores clamped 0–100 and max 3 findings.
7. **Error handling:** Catches all errors, captures to Sentry with `Sentry.captureException(e, { tags: { endpoint: "audit/preview" } })`, returns 500.

**Full report flow** (`POST /api/audit/report` at `app/api/audit/report/route.ts`):
1. Same entry + rate limiting (5/10min) + validation (name, email, URL — all required, email regex checked)
2. Scraping same as above
3. **Full AI generation:** `generateFullReport(scrapedData)` from `lib/audit.ts:175` — extended prompt requesting executive summary, 4-section analysis (SEO, conversion, brand, content — each with 5–7 structured fields), social media presence, video opportunities, 5 quick wins, 90-day growth roadmap
4. **Database persistence:** Inserts report into `reports` table (UUID generated by Postgres, JSONB `report_json`, integer `score` with CHECK 0–100), then inserts lead into `leads` table (UUID, linked to report via foreign key, status defaults to `'new'`)
5. **Email delivery:** Calls `sendReportEmail(name, email, website, score, findings, reportUrl)` from `lib/email.ts:131` — builds branded HTML template with SVG color-coded score circle (green ≥70, yellow ≥50, red <50), findings table, CTA button linking to `/report/{uuid}`, and sends via Nodemailer Gmail SMTP with connection pooling (3 connections)
6. **Response:** Returns `{ success, reportId, reportUrl }` — user sees success immediately; email arrives in ~5–7s
7. **Error handling:** Email failures are logged but don't fail the request. All other failures captured to Sentry with `endpoint: "audit/report"` tag.

#### Admin Auth Flow

**Middleware layer** (`middleware.ts:1`):
- **Matcher:** `["/itachi-7x9k/:path*"]` — only intercepts admin routes
- **Bypass:** Allows `/itachi-7x9k/login` through without authentication
- **Auth check:** Reads `socioryx_admin` cookie, compares against `ADMIN_SESSION_TOKEN` env var using edge-compatible XOR-based timing-safe comparison (`safeTokenCompare()` at `middleware.ts:3`)
- **Camouflage:** Returns HTTP 404 (not 401) on failure — completely obscures that the admin path exists

**Login endpoint** (`POST /api/itachi-7x9k/login` at `app/api/itachi-7x9k/login/route.ts`):
1. **Dual-layer rate limiting:** Per-IP (5 attempts per 15 minutes) + global (20 attempts per minute) — prevents both single-attacker and distributed brute force
2. **Sanitization:** Strips non-printable characters, caps at 200 chars
3. **Timing-safe comparison:** SHA-256 hashes both input and expected password, compares with `crypto.timingSafeEqual()` — always runs even if expected is empty to prevent timing enumeration
4. **Constant-time delay:** Adds 300–500ms random delay on failure
5. **Session:** Sets `socioryx_admin` cookie (httpOnly, secure in production, sameSite:strict, 7-day expiry, path=/)

#### Database / Data Modeling

**Schema** (`docs/audit-supabase-migration.sql`):

```sql
-- UUID primary keys (non-sequential, unguessable — OWASP compliance)
-- JSONB for AI-generated report content (schema-less, no migrations needed)
-- CHECK constraints enforce domain integrity at database level
-- Foreign key with CASCADE: deleting a report automatically cleans up its leads

CREATE TABLE reports (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  website TEXT NOT NULL,
  report_json JSONB NOT NULL,
  score INTEGER NOT NULL CHECK (score >= 0 AND score <= 100),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE leads (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  full_name TEXT NOT NULL,
  email TEXT NOT NULL,
  website TEXT NOT NULL,
  score INTEGER NOT NULL CHECK (score >= 0 AND score <= 100),
  report_id UUID NOT NULL REFERENCES reports(id) ON DELETE CASCADE,
  status TEXT NOT NULL DEFAULT 'new' CHECK (status IN ('new','contacted','qualified','closed')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

**Indexes:**
- `idx_leads_email` — supports admin search by email (`ilike` queries)
- `idx_leads_report_id` — supports lead-to-report join
- `idx_reports_website` — supports duplicate URL checks
- `idx_reports_created_at DESC` — supports time-ordered report listing
- `idx_leads_created_at DESC` — supports newest-leads-first listing

**Additional tables** (not in migration SQL, created separately):
- `contact_submissions` — contact form storage (first_name, last_name, email, subject, message, created_at)
- `posts` — blog content (id, title, slug, excerpt, content, cover_image, author, tags, published, published_at, created_at)
- `portfolio_access` — access logging for portfolio PDF downloads (firebase_uid, email, accessed_at)

**ORM pattern:** No ORM — raw Supabase TypeScript SDK (`supabase.from("table").select(...)`) with chained filters. Service-role key used server-side only (never in client bundle).

**Key decisions:**
- **Model choice:** `openai/gpt-oss-120b:free` via OpenRouter — zero-cost inference, sufficient quality for structured audit output. No fine-tuning needed for this use case.
- **Context window management:** Scraped content truncated to 8000 chars for paragraphs, preventing token overflow.
- **JSON constraint:** Prompts enforce strict JSON schema output with explicit field descriptions. `parseJsonSafely()` handles the ~40% of cases where the model deviates.
- **No embedding/vector DB:** Not needed — each audit is stateless, no retrieval or comparison across audits.
